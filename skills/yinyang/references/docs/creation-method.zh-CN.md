# 阴阳的实践总览

[首页](../../README.zh-CN.md) · [工作模型的形成与修订](../design-and-revision.zh-CN.md) · [阴阳的日常协作](https://github.com/boluopai-net/Yinyang/blob/main/skills/yinyang-empty/SKILL.zh-CN.md) · [English](creation-method.md)

形成自己的阴阳，是把采用的哲学、对实际参与者的理解和共同工作环境连接起来，
让你与模型能够继续理解、创造、判断和行动。

## 哲学与个人环境相互修订

这项实践有两个相互修订的对象：**哲学**展开对世界、价值、参与和生活方向的理解与理由；
**个人环境**使这些理解在实际合作中取得工作形式，包括 Personal 材料、六份工作描述、
提示词、Skills、工具、界面及有关的生活条件。哲学帮助判断怎样的环境值得形成，环境中的
实际工作则使哲学的前提、区分和方向接受纠正。

从哪一个开始都可以。通常先读和发展哲学，能较清楚地选择环境改变的方向；真实实践却常常
先从环境出发：一个不顺手的阅读安排、一项想完成的创作，或一次模型误解，就足以发起修订。
从当前对象做出可用结果，再把它带到另一对象中检验和发展。两者都有了可用结果以后，
再用这两个结果反过来修订组织它们的**元层方法**。

### 让可用结果改变组织它们的方法

私人版本的实际修订方法写在六份描述中的修订篇；公共版本通过本页、
[形成与修订](../design-and-revision.zh-CN.md)及[六份写作指南](../design-and-revision.zh-CN.md#基于实际材料形成情境化版本)
说明怎样使用哲学形成自己的实践。基本观点及其重要表格、哲学阅读与其他附录、导航和图示，
也参与组织这种使用。将哲学和个人环境的结果联系起来，检查这些指引原先选择的对象、
顺序、问题与判断根据是否仍然合适，并把受到影响的含义带回其实际所有者。

对象与元层可以交换角色。修订指南正在被改写时，它就是当前对象；哲学与环境的结果可以
成为判断材料。下一次用这份指南修订阅读环境时，它又成为组织工作的元层。新的阅读经验
还可以重开哲学问题。相连整体修订由模型追踪这些依赖，并把受影响的正文、附录、工作安排
和阅读面一起交付；其余内容经检查仍适用时保留。

方法与实现通常[向前演进](preference-harness.zh-CN.md#面向更有能力的模型向前演进)，
以效率与经济性比较整项工作的所得与负担，沿用有贡献的惯例，并在修订中退役过时的约定。

### 例子：从阅读安排返回学习方法

设想一位读者希望在中断后继续理解一段论证。先从环境入手，模型把原文、读者的解释与反馈放在
可同时参照的位置，并保留回到原段落的入口。接着联系哲学，辨认这项改变究竟支持了
资料取得、共同判断，还是本人解释能力的培养：页面能打开支持取得，下一次能接续论证
支持这次阅读的延续，能力发展则需要后来的实际尝试。

假设原先把独立理解的标准写成「能独自接续」，实际使用却显示，读者借助这些外部支持，
能够恢复论证、判断解释并改变帮助方式。这就为重考哲学前提提供了根据：所重视的独立性
可以改为「能找回思路、作出判断并调整所用帮助」。原先说过「想自己读懂」仍是可归属材料，
当前说明则按较后的澄清、实际表现与整体融贯表达现在采用的理解。外部支持是否确有帮助，
以及它怎样起作用，仍各自需要相应事实根据。

两边取得可用结果后，重考原来的修订方法。如果它只检查页面能否打开，就把检查问题改为
能否回到原文、恢复论证关系、继续判断并调整帮助；同时修订[科研与学习](research-and-learning.zh-CN.md#learning-purposes)
中的练习安排，以及受影响的工具指引、六份描述和基本观点。后来使用再判断这份改进后的
方法是否帮助了学习。[修订指南](../formation/revision.zh-CN.md#把文集作为相连整体修订)展开整体维护的职责。

## 从 Empty 开始

公开提供的阴阳 Skill 是 **Empty**。作者的哲学文章与图示继续作为阅读材料；你的个人版本形成自己采用的理解。

**Empty 提供递归自我改进的方法。**用自己的目的、经验、材料和判断形成个人内容，再通过实际工作持续修订。

六份描述使这项方法取得工作形式：方向、实际参与者、双方合作、实现条件，以及方法怎样改变自身。
联系阅读它们，理解一项活动，展开候选改变，比较后果，并把选定修订带入使用。
[RSI 文章](literary-recursive-improvement.zh-CN.md)展开论证，
[六份写作指南](../design-and-revision.zh-CN.md#基于实际材料形成情境化版本)说明怎样从自己的材料形成描述。

[**Empty 的方法源码**](https://github.com/boluopai-net/Yinyang/tree/main/skills/yinyang-empty)是自己的实践入口。

## 为同一方法选择辅助方式

### 模型直接写作

把自己的哲学理解、Personal 材料和已有描述交给当前使用的语言模型，按
[六份形成指南](../design-and-revision.zh-CN.md#基于实际材料形成情境化版本)直接压缩、整理和修订。
随着模型能力迭代，也让新模型重新理解材料、改善凝练。
正文保存在私人 `references/situated/` 的六份文件中，用私人 Git/GitHub 保留版本。

### 可选的记忆与综合辅助

在从 Empty 形成的个人版本上，配置辅助记忆与模型形成的社区项目。本项目已使用
[Hindsight](../hindsight.zh-CN.md)：它保留来源、整合观察，并按问题形成持续维护的正文。
模型承担配置、检查和修订，将采用的结果交回六份描述。
[Hindsight 配置指引](../hindsight.zh-CN.md#配置所选原生实现)是这条路线的操作入口。

依据实际检索、整合和维护工作能获得什么改善来选择辅助方式。两种实现保留同样的六个问题、
有归属的根据、整体检查，以及使用向方法的返回。材料、模型能力与维护成本变化时，工具选择也可以改变。

## 六份描述放在哪里，怎样使用

六份描述是取向、个人、伙伴、关系、环境和修订，位于私人 `references/situated/`；
[文件与更新约定](skill-package.zh-CN.md#公共内容与情境化内容)列出具体文件名。
个人材料、可读主题文章与来源索引放在 `references/personal/`。
原生实现也可通过私人索引连接六份完整正文。

形成与修订时，模型读取采用的哲学和有关新来源，纠正 Personal 理解，综合六份描述并联系阅读，
再把所选改动落实到工作环境，从实际使用中继续修订。
[形成与修订](../design-and-revision.zh-CN.md)展开写作方法，
[日常协作](https://github.com/boluopai-net/Yinyang/blob/main/skills/yinyang-empty/SKILL.zh-CN.md)说明怎样读取和运用当前描述。

## 从自己的现有材料开始

已有哲学、个人经验、偏好、作品或工作环境，都可以成为起点。模型帮助形成缺少的联系；
实际工作也能使你重新考虑哲学与合作方式。对进一步写作有兴趣时，
[从采用、组合到自己的创作](example-and-commons.zh-CN.md)通向个人文章与不同作品。
